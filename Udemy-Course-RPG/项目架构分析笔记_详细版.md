# 类银河恶魔城 2D RPG Demo 项目架构分析笔记

> 分析范围：`Assets/Scripts`、`Assets/Data`、`Assets/Prefab`、`Assets/InputSystem`、`ProjectSettings`、`Packages`。  
> 项目类型：Unity 6 横版动作 RPG / 类银河恶魔城练习 Demo。  
> 重点关注：模块化拆分、核心系统设计、具体实现细节、技术栈、设计模式、可复用经验与改进建议。

---

## 1. 项目整体定位

这个项目不是单纯的横版平台跳跃 Demo，而是一个已经具备完整 RPG 框架雏形的 2D 动作项目。它包含：

- 横版移动：跑、跳、下落、蹬墙、滑墙、冲刺、空中攻击。
- 动作战斗：普攻连段、跳劈、反击、远程飞剑、技能投射物、终极技领域。
- RPG 成长：属性、装备、消耗品、词条、Buff、技能树、技能点。
- 敌人 AI：巡逻、追击、攻击、眩晕、死亡、远程、法师、Boss 传送与施法。
- 关卡流程：检查点、传送门、场景入口/出口、死亡重生、回城。
- 业务系统：背包、仓库、制作、商店、任务、对话、存档、UI、音频、VFX。

整体架构的核心思路是：

```text
Entity 基类
  + 可组合组件：Health / Combat / Stats / VFX / SFX / Drop / Status
  + FSM 状态机：PlayerState / EnemyState
  + ScriptableObject 数据驱动：Item / Skill / Quest / Dialogue / Audio / DefaultStats
  + 小接口解耦：IDamagable / IInteractable / ICounterable / ISaveable
```

它的模块拆分意识是比较强的。`Player` 和 `Enemy` 并不是两个巨大脚本，而是复用 `Entity` 以及一组功能组件；玩家和敌人的行为差异主要通过状态机和少量派生类实现。

## 4. 总体模块化方式

项目可以分成 7 个大的逻辑层：

| 层 | 代表脚本 | 作用 |
|---|---|---|
| 引擎适配层 | `Entity`、`GameManager`、`AudioManager`、`UI` | 管 Unity 生命周期、场景、输入、全局服务 |
| 实体组件层 | `Entity_Health`、`Entity_Combat`、`Entity_Stats`、`Entity_VFX` | 让 Player 和 Enemy 共享通用能力 |
| 行为状态层 | `StateMachine`、`PlayerState`、`EnemyState` | 用 FSM 管移动、攻击、技能、AI |
| 数据层 | `ItemDataSO`、`Skill_DataSO`、`QuestDataSO`、`DialogueLineSO` | 通过 SO 做可配置内容 |
| 业务系统层 | `Inventory_Player`、`UI_SkillTree`、`Player_QuestManager` | 背包、技能树、任务、商店、制作 |
| 持久化层 | `SaveManager`、`GameData`、`ISaveable` | 存档读写与模块自动注册 |
| 表现层 | `Entity_VFX`、`AudioManager`、`UI_*` | 视觉、音频、界面反馈 |

这种拆分的优点是：

- 实体能力可复用：敌人和玩家都能使用生命、属性、战斗、状态效果、掉落、VFX。
- 行为差异放到状态机：玩家状态和敌人状态互不污染。
- 数据和逻辑分离：新物品、新技能、新任务主要在 Inspector 中配置。
- 存档低侵入：新增系统实现 `ISaveable` 即可参与保存。

## 5. Entity 实体系统

### 5.1 Entity 基类职责

核心文件：`Assets/Scripts/Entity/Entity.cs`

`Entity` 是玩家和敌人的共同父类，主要做底层动作能力：

- 缓存组件：`Animator`、`Rigidbody2D`、`Collider2D`、`Entity_SFX`。
- 创建状态机：`stateMachine = new StateMachine()`。
- 每帧检测地面和墙体。
- 每帧驱动当前状态：`stateMachine.UpdateActiveState()`。
- 提供移动 API：`SetVelocity(x, y)`。
- 提供翻转 API：`HandleFlip(xVelocity)`、`Flip()`。
- 提供击退：`ReciveKnockback(knockback, duration)`。
- 提供减速扩展点：`SlowDownEntity()`、`SlowDownEntityCo()`、`StopSlowDown()`。
- 提供动画事件入口：`CurrentStateAnimationTrigger()`。

地面和墙体检测：

```csharp
groundDetected = Physics2D.Raycast(groundCheck.position, Vector2.down, groundCheckDistance, whatIsGround);

wallDetected = Physics2D.Raycast(primaryWallCheck.position, Vector2.right * facingDir, wallCheckDistance, whatIsGround);
```

如果有 `secondaryWallCheck`，墙体检测需要主、副两个 Raycast 都命中。这能减少角色只在脚边或头顶蹭到墙时误判为贴墙。

翻转逻辑不是改 `localScale.x`，而是：

```csharp
transform.Rotate(0, 180, 0);
facingRight = !facingRight;
facingDir *= -1;
OnFlipped?.Invoke();
```

`OnFlipped` 事件用于 UI 小血条等子对象修正方向，例如 `UI_MiniHealthBar` 会在角色翻转后把自身 rotation 重置，避免血条也跟着反转。

### 5.2 Entity 功能组件

| 组件 | 文件 | 职责 |
|---|---|---|
| 生命 | `Entity_Health.cs` | 血量、回血、受伤、闪避、护甲/抗性减伤、击退、死亡 |
| 战斗 | `Entity_Combat.cs` | 攻击范围检测、伤害生成、命中反馈、音效/VFX 触发 |
| 属性 | `Entity_Stats.cs` | 伤害公式、防御公式、主属性加成、默认属性套用 |
| 状态 | `Entity_StatusHandler.cs` | 冰冻、灼烧、感电三类元素异常 |
| 掉落 | `Entity_DropManager.cs` | 死亡或宝箱开启时掉落物品 |
| 视觉 | `Entity_VFX.cs` | 受击闪白、残影、命中特效、元素颜色 |
| 音效 | `Entity_SFX.cs` | 实体攻击命中/落空音效入口 |
| 动画事件 | `Entity_AnimationTriggers.cs` | Animation Event 调用当前状态或攻击判定 |

这个设计是典型的 Unity 组件式架构。`Entity` 只提供通用基础能力，不负责“血量怎么算”“攻击打谁”“掉什么东西”。这些都拆成独立组件，通过 `GetComponent<T>()` 组合在同一个 GameObject 上。

### 5.3 生命模块

核心文件：`Entity_Health.cs`

重要字段：

- `currentHealth`
- `isDead`
- `regenInterval`
- `canRegenerateHealth`
- `lastDamageTaken`
- `canTakenDamage`
- 普通击退与重击击退：`knockbackPower`、`heavyKnockbackPower`
- 重击阈值：`heavyDamageThreshold`

受伤流程：

```text
TakeDamage()
  1. 死亡或无敌则返回 false
  2. 闪避判定
  3. 从攻击者身上读取 Entity_Stats，获取 armorReduction
  4. 被攻击者用自身 Stats 计算护甲减伤和元素抗性
  5. 计算物理伤害与元素伤害
  6. 根据物理伤害决定击退强度
  7. ReduceHealth()
  8. 触发 OnTakingDamage
  9. 返回 true 表示命中成功
```

防御侧处理发生在被打者身上，这点设计得比较合理：攻击者只提供原始伤害和穿甲，被攻击者根据自己的护甲、抗性、闪避来结算最终伤害。

死亡流程：

```text
ReduceHealth()
  -> currentHealth <= 0
  -> Die()
  -> isDead = true
  -> entity.EntityDeath()
  -> dropManager?.DropItems()
```

玩家生命派生类 `Player_Health` 在死亡时额外打开死亡 UI：

```csharp
player.ui.OpenDeathScreenUI();
```

### 5.4 战斗模块

核心文件：`Entity_Combat.cs`

近战攻击使用圆形范围检测：

```csharp
Physics2D.OverlapCircleAll(targetCheck.position, targetCheckRadius, whatIsTarget)
```

攻击对象不是强依赖 `Enemy`，而是读取接口：

```csharp
IDamagable damagable = target.GetComponentInParent<IDamagable>();
```

因此敌人、玩家、宝箱、技能分身生命体，只要实现 `IDamagable`，都可以被统一攻击。

完整攻击流程：

```text
PerformAttack()
  -> 找范围内 Collider
  -> 找 IDamagable
  -> stats.GetAttackData(basicAttackScale)
  -> damagable.TakeDamage(physical, elemental, element, attacker)
  -> 如果有元素，给目标 Entity_StatusHandler 施加状态
  -> 如果命中，触发 OnDoingPhysicalDamage
  -> 创建命中 VFX
  -> 播放命中音效，否则播放 Miss 音效
```

`OnDoingPhysicalDamage` 是一个很好的扩展点。装备效果 `ItemEffect_HealOnDoingDamage` 就订阅这个事件来做吸血效果。

### 5.5 元素状态模块

核心文件：`Entity_StatusHandler.cs`

支持三类元素：

- Ice：减速，播放蓝色闪烁 VFX。
- Fire：持续灼烧 DOT，每秒 2 跳。
- Lightning：感电充能，达到最大充能后触发雷击伤害。

限制逻辑：

```csharp
public bool CanBeApplied(ElementType element)
{
    if (element == ElementType.Lightning && currentEffect == ElementType.Lightning)
        return true;

    return currentEffect == ElementType.None;
}
```

这表示同一时间只能有一种主要异常，但 Lightning 允许重复叠 charge。

冰冻减速会调用实体自身的 `SlowDownEntity()`。玩家和敌人分别覆写减速逻辑：

- 玩家减速：移动速度、跳跃力、动画速度、墙跳力、跳劈速度、普攻位移一起缩放。
- 敌人减速：`activeSlowMultiplier` 影响巡逻速度和战斗速度，并缩放动画速度。

## 6. 属性系统

### 6.1 基础设计

核心文件：

- `Stat.cs`
- `Stat_ResourcesGroup.cs`
- `Stat_OffenseGroup.cs`
- `Stat_DefenseGroup.cs`
- `Stat_MajorGroup.cs`
- `Entity_Stats.cs`

属性系统的基本模型是：

```text
最终属性值 = baseValue + 所有 modifier.value
```

每个 `Stat` 包含：

- `baseValue`
- `List<StatModifier>`
- `needToCaculate`
- `finalValue`

`needToCaculate` 是脏标记。只有属性被修改后，下次读取才重新计算：

```csharp
public float GetValue()
{
    if (needToCaculate)
    {
        finalValue = GetFinalValue();
        needToCaculate = false;
    }

    return finalValue;
}
```

这对 RPG 属性系统很实用。UI、战斗、移动可能频繁读取属性，但属性本身不是每帧变化，用缓存可以避免无意义计算。

### 6.2 修饰器来源追踪

每个 modifier 都记录来源：

```csharp
public class StatModifier
{
    public float value;
    public string source;
}
```

装备加属性时用 `itemId` 作为 source，卸装时按 source 删除：

```csharp
statToModify.AddModifier(modifier.value, itemId);
statToModify.RemoveModifier(itemId);
```

这样可以避免多个装备或 Buff 改同一属性时互相误删。这个细节很重要，很多 RPG 背包系统的属性 bug 都出在“加成能加上去，但卸不干净或误删其他来源”。

### 6.3 属性分组

| 分组 | 属性 |
|---|---|
| Resources | `maxHealth`、`healthRegen` |
| Major | `strength`、`agility`、`intelligence`、`vitality` |
| Offense | `damage`、`critPower`、`critChance`、`armorReduction`、`attackSpeed`、三元素伤害 |
| Defense | `armor`、`evasion`、三元素抗性 |

### 6.4 主属性加成规则

`Entity_Stats` 中写死了一套主属性换算：

| 主属性 | 加成 |
|---|---|
| Strength | 每点 +1 基础物理伤害，+0.5 暴击伤害 |
| Agility | 每点 +0.3 暴击率，+0.5 闪避 |
| Intelligence | 每点 +1 元素伤害奖励，+0.5 元素抗性 |
| Vitality | 每点 +5 最大生命，+1 护甲 |

例如：

```csharp
public float GetBaseDamage() => offense.damage.GetValue() + major.strength.GetValue();
public float GetCritChance() => offense.critChance.GetValue() + major.agility.GetValue() * 0.3f;
public float GetMaxHealth() => resources.maxHealth.GetValue() + major.vitality.GetValue() * 5;
```

### 6.5 伤害公式

攻击数据由 `AttackData` 封装：

```text
AttackData
  physicalDamage
  elementDamage
  isCrit
  element
  effectData
```

物理伤害：

```csharp
isCrit = Random.Range(0, 100) < critChance;
finalDamage = isCrit ? baseDamage * critPower : baseDamage;
```

注意：`critPower` 是除以 100 后作为倍数使用。如果暴击伤害配置为 150，则暴击后是 `baseDamage * 1.5`。

元素伤害：

```text
1. 读取 fire / ice / lightning
2. 选最高的一项作为本次元素类型
3. 其他两个元素贡献 50% 伤害
4. intelligence 作为额外元素伤害奖励
```

这样设计可以让玩家主堆一种元素，但副元素也不是完全浪费。

### 6.6 防御公式

护甲减伤：

```csharp
effectiveArmor = totalArmor * (1 - armorReduction);
mitigation = effectiveArmor / (effectiveArmor + 100);
final = Clamp(mitigation, 0, 0.85);
```

元素抗性：

```csharp
resistance = baseResistance + intelligence * 0.5f;
finalResistance = Clamp(resistance, 0, 75) / 100;
```

闪避：

```csharp
totalEvasion = defense.evasion + agility * 0.5f;
finalEvasion = Clamp(totalEvasion, 0, 70);
```

这里有一个小不一致：`UI_StatToolTip` 文案里写闪避上限 85%，但代码实际是 70%。

## 7. FSM 状态机系统

### 7.1 核心结构

核心文件：

- `StateMachine.cs`
- `EntityState.cs`
- `PlayerState.cs`
- `EnemyState.cs`

`StateMachine` 非常小：

```csharp
public class StateMachine
{
    public EntityState currentSate { get; private set; }
    public bool canChangeState = true;

    public void Initialize(EntityState startState)
    public void ChangeState(EntityState newState)
    public void UpdateActiveState()
    public void SwitchOffStateMachine()
}
```

状态切换流程：

```text
Initialize(start)
  -> currentState = start
  -> start.Enter()

ChangeState(new)
  -> current.Exit()
  -> current = new
  -> new.Enter()

UpdateActiveState()
  -> current.Update()
```

### 7.2 EntityState 基类

每个状态都拿到：

- `StateMachine`
- `animBoolName`
- `Animator`
- `Rigidbody2D`
- `Entity_Stats`
- `stateTimer`
- `triggerCalled`

生命周期：

```text
Enter()  -> anim.SetBool(animBoolName, true)
Update() -> stateTimer -= Time.deltaTime; UpdateAnimationParameters()
Exit()   -> anim.SetBool(animBoolName, false)
```

`AnimationTrigger()` 把 `triggerCalled` 设为 true。动画片段通过 Animation Event 调 `Entity_AnimationTriggers.CurrentStateTrigger()`，再转到当前状态。这是攻击、跳劈、施法等状态退出的关键。

### 7.3 PlayerState 中间层

`PlayerState` 注入：

- `Player`
- `PlayerInputSet`
- `Player_SkillManager`

它在所有玩家状态的 `Update()` 中统一处理两个全局技能：

- Dash：按下 Dash 且 `CanDash()` 通过，进入 `dashState`。
- DomainExpansion：按下 R 且终极技可用，根据技能升级决定直接创建领域还是进入升空施法状态。

这避免了每个玩家状态都重复写冲刺和终极技输入判断。

### 7.4 EnemyState 中间层

`EnemyState` 注入：

- `Enemy`
- `Rigidbody2D`
- `Animator`
- `Entity_Stats`

它统一更新敌人动画参数：

- `battleAnimSpeedMultiplier`
- `moveAnimSpeedMultiplier`
- `xVelocity`

这样敌人移动速度、战斗速度、减速状态都能影响动画播放观感。

### 8.4 普攻连段

核心文件：`Player_BasicAttackState.cs`

机制：

- `comboIndex` 从 1 开始，对应 Animator 的 `basicAttackIndex`。
- `comboLimit` 默认 3，并根据 `player.attackVelocity.Length` 校正。
- 每段攻击有独立位移 `attackVelocity[comboIndex - 1]`。
- 如果在攻击状态中再次按 Attack，则 `comboAttackQueued = true`。
- 当前攻击动画触发 `triggerCalled` 后，如果已排队下一段，就下一帧重新进入 `basicAttackState`。

为什么要下一帧再进入？

```csharp
anim.SetBool(animBoolName, false);
player.EnterAttaclStateWithDelay();
```

作者注释里也提到，这是为了避免同一帧内 bool 状态切换不稳定，导致 Animator 没有真正从旧状态退出。这里是很典型的 Unity Animator/FSM 交互细节。

### 8.5 Dash 状态

核心文件：`Player_DashState.cs`

进入 Dash：

- 调用 `skillManager.dash.OnStartEffect()`，触发技能升级效果。
- 播放残影：`player.vfx.DoImageEchoEffect(player.dashDuration)`。
- 保存并清零重力：`rb.gravityScale = 0`。
- 锁定冲刺方向。
- 关闭受伤：`player.health.SetCanTakenDamage(false)`。
- 切到 `Untargetable` Layer。

退出 Dash：

- 调用 `skillManager.dash.OnEndEffect()`。
- 速度归零。
- 恢复重力。
- 设置玩家自己的 Dash 限制冷却 `dashCoolDown`。
- 恢复受伤。
- 切回 `Player` Layer。

这里有两套冷却概念：

- 技能系统的 `cooldown`，用于 UI 和技能解锁后的全局 CD。
- Player 自己的 `dashCoolDown/dashLimitDuration`，像是额外防抖或调试用限制。

### 8.6 反击状态

核心文件：

- `Player_CounterAttackState.cs`

```csharp
foreach (var target in GetDectedColliders(whatIsCounterable))
{
    ICounterable counterable = target.GetComponent<ICounterable>();
    if (counterable.CanBeCountered)
        counterable.HandleCounter();
}
```

敌人的可反击窗口由动画事件控制：

- `EnableCounterWindow()`
- `DisableCounterWindow()`

同时显示敌人头上的攻击警告 VFX。

## 9. 敌人 AI 系统

### 9.1 Enemy 基类

核心文件：`Enemy.cs`

`Enemy` 继承 `Entity`，新增：

- 敌人通用状态：idle、move、attack、battle、dead、stunned。
- 战斗参数：追击速度、攻击距离、攻击冷却、战斗持续时间、后撤距离。
- 眩晕参数：眩晕时间、眩晕击退、是否可被反击。
- 玩家检测：Raycast 向前检测玩家，同时被地形阻挡。
- 玩家死亡事件处理：玩家死后敌人回 idle。

玩家检测：

```csharp
Physics2D.Raycast(playerCheck.position, Vector2.right * facingDir, playerCheckDistance, whatIsPlayer | whatIsGround)
```

如果 Raycast 第一个命中不是 Player，就返回 default。这个设计使墙体能遮挡敌人视线。

### 9.2 通用敌人状态

```text
Enemy_GroundedState
  -> 检测到玩家进入 battle

Enemy_IdleState
  -> 等 idleTime 后进入 move

Enemy_MoveState
  -> 朝 facingDir 巡逻，遇墙/无地面回 idle

Enemy_BattleState
  -> 更新目标与战斗计时
  -> 超过 battleTimeDuration 回 idle
  -> 在 attackDistance 内且冷却完成进入 attack
  -> 否则追击或原地保持

Enemy_AttackState
  -> 同步攻击速度
  -> 等动画 trigger 后回 battle

Enemy_StunnedState
  -> 关闭反击窗口和警告
  -> 施加眩晕击退
  -> 计时结束回 idle

Enemy_DeadState
  -> 关闭动画和碰撞
  -> 施加向上死亡弹飞
  -> 关闭状态机
  -> 延迟 Destroy
```

### 9.3 不同敌人的扩展

#### Skeleton

文件：`Enemy_Skeleton.cs`

最标准的近战敌人，只初始化通用状态，并实现 `ICounterable`。

#### Slime

文件：`Enemy_Slime.cs`

特点：

- 死亡状态换成 `Enemy_SlimeDeadState`。
- 死亡时 `CreateSlimeOnDeath()` 分裂生成多个小史莱姆。
- 子史莱姆用 `AdjustStatSetup()` 根据父对象属性缩放：
  - 血量、防御按 penalty 缩放。
  - 攻击属性按 increase 缩放。
- 生成后给随机速度，并协程延迟一帧进入战斗状态。

#### Archer Elf

文件：

- `Enemy_ArcherElf.cs`
- `Enemy_ArcherElfBattleState.cs`
- `Enemy_ArcherElfArrow.cs`

特点：

- 专用 BattleState 会保持距离。
- 太近时后退，遇死路停止。
- 攻击动画事件生成箭。
- 箭实现 `ICounterable`，玩家反击后箭会反向飞行，并把 Enemy Layer 加入目标层，形成“反弹箭打敌人”的玩法。

#### Mage

文件：

- `Enemy_Mage.cs`
- `Enemy_MageBattleState.cs`
- `Enemy_MageRetreatState.cs`
- `Enemy_MageSpellCastState.cs`
- `Enemy_MageProjectile.cs`

特点：

- 太近时优先使用 RetreatState。
- 后撤时切 `Untargetable` Layer，并播放残影。
- 后撤到最大距离或背后不能继续移动时进入施法。
- 法术是抛物线投射物，用重力公式计算初速度。

抛物线计算核心：

```text
timeToApex = sqrt(2 * peakHeight / gravity)
timeFromApex = sqrt(2 * (peakHeight - displacementY) / gravity)
velocityX = displacementX / totalTime
velocityY = sqrt(2 * gravity * peakHeight)
```

#### Reaper

文件：

- `Enemy_Reaper.cs`
- `Enemy_ReaperBattleState.cs`
- `Enemy_ReaperAttackState.cs`
- `Enemy_ReaperTeleportState.cs`
- `Enemy_ReaperSpellCastState.cs`
- `Enemy_ReaperSpell.cs`

这是 Boss 型敌人，特点更多：

- 战斗状态有最大停留时间，超时进入传送。
- 攻击结束后按概率决定是否传送。
- 传送概率会逐次增加，成功传送后重置。
- 传送点从 arenaBounds 内随机 X 位置向下 Raycast 找地面。
- 施法有冷却，法术会根据玩家移动方向预判偏移位置。
- 传送期间切 `Untargetable`。

这是项目里 AI 扩展性最强的例子：同一个 Enemy 骨架，通过替换 Battle/Attack/Teleport/SpellCast 状态，就能做出明显不同的 Boss 行为。

### 10.2 Skill_Base

每个技能都有：

- `SkillType skillType`
- `SkillUpgradeType upgradeType`
- `float cooldown`
- `float lastTimeUsed`
- `DamageScaleData damageScaleData`

技能解锁由 `upgradeType != None` 判断。技能升级来自 `Skill_DataSO`：

```csharp
public void SetSkillUpgrade(Skill_DataSO skillData)
{
    UpagradeData upgrade = skillData.upagradeData;
    upgradeType = upgrade.upgradeType;
    cooldown = upgrade.cooldown;
    damageScaleData = upgrade.damageScaleData;
    player.ui.inGameUI.GetSkillSlot(skillType).SetupSkillSlot(skillData);
    ReSetCooldown();
}
```

这意味着当前实现中每个技能同一时间只有一个升级形态，而不是多节点叠加式升级。

### 10.3 Dash 技能

文件：`Skill_Dash.cs`

Dash 的基础位移和无敌在 `Player_DashState` 中实现，`Skill_Dash` 只负责升级附加效果：

- 起点创建时间残影。
- 起点和终点都创建时间残影。
- 起点创建碎片。
- 起点和终点都创建碎片。

这说明技能系统和玩家状态机目前是“分工但有耦合”的：冲刺过程归状态机，冲刺附加效果归技能类。

### 10.4 Shard 技能

文件：

- `Skill_Shard.cs`
- `SkillObject_Shard.cs`

升级形态：

- 普通碎片：生成后定时爆炸。
- 移动碎片：追踪最近敌人。
- 多重施法：有 charge，逐个恢复。
- 传送碎片：再次按技能时与碎片交换位置。
- 传送加血量回溯：交换位置后恢复到释放时保存的血量百分比。

关键点：

```csharp
currentShard.OnExplode += ForceCooldown;
```

传送类碎片如果玩家一直不二段触发，碎片爆炸时会强制让技能进入冷却，避免技能长期处于“未消耗冷却”的状态。

### 10.5 SwordThrow 技能

文件：

- `Skill_SwordThrow.cs`
- `Player_SwordThrowState.cs`
- `SkillObject_Sword*.cs`

流程：

```text
右键按下
  -> 进入 Player_SwordThrowState
  -> 显示轨迹点
  -> 每帧用鼠标方向预测抛物线轨迹
左键确认
  -> Animator 设置 swordThrowPerformed
  -> 动画事件 ThrowSword()
  -> 实例化对应飞剑预制体
```

轨迹预测公式：

```csharp
predictedPoint = initialVelocity * t + 0.5f * Physics2D.gravity * swordGravity * t * t
```

飞剑形态：

- Regular：命中后停在目标上，可再次按键召回。
- Pierce：可穿透若干目标或命中地面后停止。
- Spin：到最大距离后停止物理模拟，在原地按频率范围攻击，持续一段时间后召回。
- Bounce：命中后在附近敌人之间弹射，记录已命中过的目标，弹射耗尽后召回。

### 10.6 TimeEcho 技能

文件：

- `Skill_TimeEcho.cs`
- `SkillObject_TimeEcho.cs`
- `SkillObject_Health.cs`

TimeEcho 是时间残影：

- 可攻击一次或多次。
- 命中后有概率复制一个新的 Echo。
- 死亡或持续时间到后，如果是 Wisp 升级，会变成光球飞回玩家。
- 光球触碰玩家后可回血、减冷却或净化负面效果。

Wisp 回到玩家时不是直线，而是用了 PerlinNoise 生成曲线路径：

```csharp
Vector2 perpendicular = new Vector2(-dir.y, dir.x);
float noise = Mathf.PerlinNoise(Time.time * 2f, noiseSeed) - 0.5f;
Vector2 finalDir = dir + perpendicular * noise * 2f;
```

这是一个很适合学习的小细节：简单几行代码就能让回收物体的运动更自然。

### 10.7 DomainExpansion 终极技

文件：

- `Skill_DomainExpansion.cs`
- `SkillObject_DomainExpansion.cs`
- `Player_DomainExpansionState.cs`

终极技有两类执行方式：

- 即时领域：直接创建领域。
- 施法领域：玩家升空悬停，在领域持续期间持续投放 Echo 或 Shard。

`Player_DomainExpansionState` 负责升空和悬停：

```text
Enter
  -> 保存重力
  -> 向上移动
  -> 关闭受伤

Update
  -> 到达最大上升距离后 Levitate()
  -> 重力设为 0
  -> 创建领域
  -> 持续 DoSpellCasting()

Exit
  -> 恢复受伤
```

`SkillObject_DomainExpansion`：

- 从 0 缩放到最大领域大小。
- 进入领域的敌人加入 `trappedTargets`，并调用 `enemy.SlowDownEntity(duration, slowDownPercent, true)`。
- 结束时缩小到 0，清空目标并停止减速。

## 12. 掉落系统

核心文件：`Entity_DropManager.cs`

掉落数据来自 `ItemListDataSO dropData`。

掉落流程：

```text
DropItems()
  -> RollDrops()
  -> 取不超过 maxItemsToDrop 的结果
  -> CreateItemDrop()
```

`ItemDataSO.GetDropChance()`：

```csharp
chance = ((1000 - itemRarity + 1) / 1000) * 100;
return Mathf.Min(chance, maxDropChance);
```

稀有度越高，掉率越低。通过 `maxDropChance` 限制最高掉率。

`RollDrops()`：

1. 每个物品先按掉率独立判定是否进入候选。
2. 候选按 `itemRarity` 从高到低排序。
3. 用 `maxRarityAmount` 控制总掉落稀有度预算。
4. 最多掉 `maxItemsToDrop` 个。

这是一种简单的“掉落预算”算法，可以避免一次掉太多高稀有物品。

## 15. 存档系统

### 15.1 结构

核心文件：

- `SaveManager.cs`
- `GameData.cs`
- `FileDataHandler.cs`
- `SerializableDictionary.cs`
- `ISaveable.cs`

总体流程：

```text
SaveManager.Start()

  -> FindISaveables()

  -> LoadGame()

LoadGame()

  -> 没有存档则 new GameData()

  -> 所有 ISaveable.SaveData(ref data)

    .OfType<ISaveable>()
    .ToList();
```

这意味着任何系统只要实现 `ISaveable`，就能自动进入存档流程，不需要手动注册到 SaveManager。

当前实现了存档的模块包括：

- 玩家背包。
- 仓库。
- 技能树。
- 任务。
- 检查点。
- 传送门。
- 游戏管理器的最后场景与位置。
- Quest UI 读取已完成任务数据用于过滤。

### 15.3 GameData

`GameData` 是一个集中式数据容器：

```text
gold
inventory
storageItems
storageMaterials
equipedItems
skillPoints
skillTreeUI
skillUpgrades
unlockedCheckpoints
inScenePortals
completedQuests
activeQuests
portalDestinationSceneName
returningFromTown
lastScenePlayed
lastPlayerPosition
```

Unity 的 `JsonUtility` 不支持普通 Dictionary，于是项目自定义了 `SerializableDictionary<TKey,TValue>`，序列化前把字典拆成 keys/values 两个 List，反序列化后再还原。

### 15.4 文件读写与加密

`FileDataHandler` 保存到：

```csharp
Application.persistentDataPath + "/unitylzydev.json"
```

数据序列化：

```csharp
JsonUtility.ToJson(gameData, true)
```

加密只是 XOR 混淆：

```csharp
modifiedData += (char)(data[i] ^ codeWord[i % codeWord.Length]);
```

这不是安全意义上的加密，但足够防止玩家直接肉眼改 JSON。

## 16. 场景、重生、检查点、传送门

### 16.1 GameManager

核心文件：`GameManager.cs`

`GameManager` 是单例并 `DontDestroyOnLoad`。

场景切换流程：

```text
ChangeScene(sceneName, respawnType)
  -> SaveManager.SaveGame()
  -> Time.timeScale = 1
  -> StartCoroutine(ChangeSceneCo)

ChangeSceneCo
  -> Fade Out
  -> LoadScene
  -> 等待 SaveManager / GameManager LoadData 完成
  -> Fade In
  -> 根据 RespawnType 计算玩家新位置
  -> Player.TeleportPlayer(position)
```

重生类型：

- `Enter`
- `Exit`
- `NonSpecific`
- `Portal`

`NonSpecific` 很重要。死亡重生或继续游戏时，它会：

1. 找到所有已解锁 Checkpoint。
2. 找到所有 Enter Waypoint。
3. 合并这些位置。
4. 选距离 `lastPlayerPosition` 最近的点。

这比固定回到某个出生点更合理。

### 16.2 Checkpoint

核心文件：`Object_Checkpoint.cs`

检查点：

- 触发后激活动画和火焰音效。
- `checkpointId` 在 `OnValidate()` 中自动生成 GUID。
- 存档只保存已激活检查点。

### 16.3 Waypoint

核心文件：`Object_Waypoint.cs`

Waypoint 用于场景之间的入口/出口：

- `waypointType = Enter` 时，连接点自动设为 `Exit`。
- `waypointType = Exit` 时，连接点自动设为 `Enter`。
- 触发后调用 `GameManager.ChangeScene(transferToScene, conntedWaypoint)`。

### 16.4 Portal

核心文件：

- `Object_Portal.cs`
- `ItemEffect_PortalScroll.cs`

传送门用于回城：

- 在非城镇场景使用卷轴，创建传送门。
- 从传送门进入城镇。
- 城镇中的传送门可以返回原场景。
- 存档记录每个场景中的传送门位置。
- 从城镇返回后，传送门可自动清理。

这个系统通过 `GameData.inScenePortals`、`portalDestinationSceneName`、`returningFromTown` 维护跨场景状态。

## 22. 设计模式总结

| 设计思路 | 使用位置 | 说明 |
|---|---|---|
| 组件模式 | `Entity` + `Entity_*` | 把生命、战斗、属性、VFX、掉落拆成独立组件 |
| 状态模式 | `StateMachine` + `EntityState` | 玩家动作和敌人 AI 都是状态对象 |
| 模板方法 | `Enter/Update/Exit` | 状态生命周期统一，子类填具体逻辑 |
| 策略模式 | `ItemEffect_DataSO` | 每种物品效果独立成一个策略 |
| 观察者模式 | C# event | 血量更新、受伤、伤害事件、翻转事件 |
| 单例 | `Player`、`UI`、`GameManager`、`SaveManager`、`AudioManager` | 全局访问方便，但也增加耦合 |
| 接口隔离 | `IDamagable`、`IInteractable`、`ICounterable`、`ISaveable` | 小接口降低系统直接依赖 |
| 数据驱动 | ScriptableObject | 技能、物品、任务、对话、音频都配置化 |
| 脏标记 | `Stat.needToCaculate` | 属性值惰性计算 |
| 事件驱动 UI | `OnInventoryChange`、`OnHealthUpdate` | 数据变化时刷新 UI |

## 23. 值得学习的关键细节

### 23.1 Entity 只做基础能力，系统能力用组件组合

这是项目最值得学的地方。`Player` 和 `Enemy` 没有各写一套生命、伤害、属性，而是共享：

```text
Entity_Health
Entity_Combat
Entity_Stats
Entity_StatusHandler
Entity_DropManager
Entity_VFX
Entity_SFX
```

以后你做新项目时，可以直接复用这种拆法。

### 23.2 FSM 中间层设计合理

`EntityState -> PlayerState -> 具体状态` 和 `EntityState -> EnemyState -> 具体状态` 这个三层结构很舒服：

- `EntityState` 放所有状态通用的 Animator、Rigidbody、Stats、Timer。
- `PlayerState` 放玩家输入和技能管理。
- `EnemyState` 放敌人动画参数和 Enemy 引用。

这样不会让每个状态都重复构造依赖。

### 23.3 攻击通过 IDamagable 解耦

攻击不关心目标是不是 Enemy：

```csharp
IDamagable damagable = target.GetComponentInParent<IDamagable>();
```

所以宝箱、分身、玩家、敌人都能接入同一套攻击逻辑。

### 23.4 Animation Event 与 FSM 配合

攻击状态不是用固定秒数退出，而是等动画事件：

```text
Animation Event
  -> Entity_AnimationTriggers.CurrentStateTrigger()
  -> Entity.CurrentStateAnimationTrigger()
  -> currentState.AnimationTrigger()
  -> triggerCalled = true
```

这样动画速度改变时，攻击判定和退出仍然跟动画帧同步。

### 23.5 属性 modifier 使用 source

装备卸下、Buff 结束都能精准删除自己加的 modifier。这是 RPG 属性系统稳定性的关键。

### 23.6 技能树把 UI 节点和技能升级打通

技能树节点解锁后直接调用：

```csharp
skillTree.skillManager.GetSkillByType(skillData.skillType).SetSkillUpgrade(skillData);
```

也就是说，UI 节点不是单纯显示，它确实驱动了玩家技能行为变化。

### 23.7 存档系统通过接口自动发现

新增一个需要存档的系统，只要实现：

```csharp
public void LoadData(GameData data)
public void SaveData(ref GameData data)
```

就能自动被 `SaveManager` 找到。这个比在 SaveManager 里手写一堆引用要好维护。

## 24. 当前实现中的问题与改进建议

这些不是否定项目，而是作为学习笔记时很值得记录的工程细节。

### 24.1 GetComponent 隐式依赖较多

大量组件在 `Awake()` 中自己 `GetComponent`：

```csharp
entityStats = GetComponent<Entity_Stats>();
entityVfx = GetComponent<Entity_VFX>();
dropManager = GetComponent<Entity_DropManager>();
```

问题是漏挂组件时可能静默失败。建议：

- 给关键组件加 `[RequireComponent]`。
- `Awake()` 中对必要依赖做 null 检查并 `Debug.LogError`。
- 对复杂对象可以做显式 Initialize。

### 24.2 高频 Instantiate/Destroy 没有对象池

残影、碎片、飞剑、命中特效、掉落物都直接 `Instantiate()` 和 `Destroy()`。

战斗密集时容易产生 GC 压力。优先池化：

1. 残影 prefab。
2. 命中 VFX。
3. 技能投射物。
4. 掉落物。

### 24.3 `Entity_Combat.PerformAttackOnTarget` 忽略传入的 DamageScaleData

代码里创建了：

```csharp
DamageScaleData damageScale = damageScaleData == null ? basicAttackScale : damageScaleData;
```

但真正用的是：

```csharp
AttackData attackData = stats.GetAttackData(basicAttackScale);
```

这会导致传入的 `damageScaleData` 没生效。比如 Reaper spell 调用 `PerformAttackOnTarget(collision.transform, damageScaleData)`，理论上应该用法术伤害缩放，但当前实现仍可能使用基础攻击缩放。

建议改成：

```csharp
AttackData attackData = stats.GetAttackData(damageScale);
```

### 24.4 `Entity_Health.UpdataHealthBar` 空引用判断有风险

当前：

```csharp
if (healthBar == null && healthBar.transform.parent.gameObject.activeSelf == false)
    return;
```

如果 `healthBar == null` 为 true，后半句仍会访问 `healthBar.transform`，会空引用。应该改成：

```csharp
if (healthBar == null || healthBar.transform.parent.gameObject.activeSelf == false)
    return;
```

### 24.5 ItemEffect 中有运行时查找对象的情况

例如：

```csharp
Player player = FindAnyObjectByType<Player>();
UI ui = FindAnyObjectByType<UI>();
```

这让 SO 效果依赖场景查找。更稳的方式是统一让调用方传上下文：

```csharp
ExecuteEffect(Player player)
```

当前 `ItemEffect_Buff` 已经部分这么做，但接口没有统一。

### 24.6 `ItemEffect_PortalScroll` 在城镇中只 Log 不 return

代码：

```csharp
if (SceneManager.GetActiveScene().name == "Level_0")
{
    Debug.Log("Cannot open portal in town!");
}

Object_Portal.instance.ActivatePortal(portalPosition);
```

这会导致城镇中仍然继续创建传送门。应该在 Log 后 `return`。

### 24.7 `Inventory_Storage.ConsumedMaterialsAmount` 在 foreach 中 Remove

在 `foreach (var item in itemList)` 中直接 `itemList.Remove(item)` 有集合修改风险。建议改成 for 倒序遍历，或先记录待删项。

### 24.8 GameData 会越来越膨胀

当前所有系统数据都堆在一个 `GameData` 类里。功能继续增加后会变成巨大数据类。

可以按系统拆分：

```csharp
public InventorySaveData inventory;
public SkillSaveData skills;
public QuestSaveData quests;
public WorldSaveData world;
```

### 24.9 静态单例和静态事件方便但耦合高

项目大量使用：

- `Player.instance`
- `UI.instance`
- `GameManager.instance`
- `SaveManager.instance`
- `AudioManager.instance`
- `Player.OnPlayerDeath`

课程项目没问题，商业项目建议集中到服务层或 EventBus，至少要保证场景切换时解绑彻底。

### 24.10 拼写和调试残留较多

常见拼写问题：

- `qurstTargetId`
- `dutation`
- `encrpyData`
- `upagradeData`
- `ChracaterUI`
- `Peirce`
- `secound`
- `GetMoceSpeed`

还有不少 `Debug.Log` 和注释掉的大段旧代码。建议后期清理，保持可维护性。

## 27. 总结

这个项目的价值不在于某个单独功能多复杂，而在于它把一个 2D 动作 RPG 的主要系统都串起来了。它已经具备一套清晰的模块化骨架：

- 实体能力组件化。
- 行为用状态机表达。
- 内容用 ScriptableObject 配置。
- 战斗通过接口解耦目标。
- 属性通过 modifier 和 source 管理加成。
- UI 通过事件刷新。
- 存档通过 `ISaveable` 自动发现。

如果把它当作学习项目，最建议重点吸收三件事：

1. `Entity + 组件 + FSM` 的角色架构。
2. `ScriptableObject + 运行时实例` 的数据驱动方式。
3. `接口 + 事件` 带来的低耦合扩展点。

后续如果要把它推进到更完整的项目，优先做对象池、依赖检查、技能职责收敛、存档数据拆分、代码清理和单元测试。这样它就会从一个课程 Demo 骨架，逐步变成更稳定的可扩展游戏框架。
