# 战斗系统深度分析

## 1. 系统定位：解决什么问题？

战斗系统负责从"攻击指令发出"到"伤害作用到目标身上完成反馈"的**全流程**。核心职责：

1. **攻击检测**：攻击动画播放时，在正确的时刻检测命中哪些目标
2. **伤害计算**：综合角色属性（攻击力、暴击、元素伤害）生成伤害数据
3. **伤害结算**：综合防御方属性（护甲、闪避、元素抗性）计算最终受伤
4. **状态效果**：元素伤害附带减速/灼烧/感电效果
5. **反馈表现**：命中 VFX、受击闪白、击退、音效
6. **反击机制**：特定敌人的攻击可被玩家精确反击

**在项目中的位置：** 战斗系统是属性系统和状态机系统的"交汇点"——状态机决定"什么时候打"，属性系统提供"打多少伤害"，战斗系统负责把两者串起来并在目标身上兑现结果。

**如果没有这个系统会怎样？**

```csharp
// 反面：新手常见——在 Update 里硬编码一切
void Update() {
    if (Input.GetKeyDown(KeyCode.J)) {
        anim.Play("Attack");
        // 伤害判定用代码计时——动画速度一改就全错了
        Invoke("DoDamage", 0.3f);
    }
}
void DoDamage() {
    // 敌人检测靠硬编码的 Transform.Find / Tag
    GameObject enemy = GameObject.FindWithTag("Enemy");
    enemy.GetComponent<Health>().hp -= 10;
}
```

问题：攻击和受击耦合在一起、命中判定时机与动画脱节、敌人筛选无规则、伤害计算无体系。

## 2. 设计思路：为什么这样设计？

### 2.1 架构选型：Animation Event 驱动的攻击判定

项目选了一个经典的动作游戏方案——**动画事件在精确帧触发攻击判定**：

```
动画播放 → 武器挥到目标的那一帧 → Animation Event 触发 AttackTrigger()
         → Entity_AnimationTriggers.AttackTrigger()
         → Entity_Combat.PerformAttack()
         → OverlapCircleAll 检测范围内的可攻击目标
```

**为什么不放在 Update 里轮询？**

如果每帧检测"攻击动画是否在第 N 帧"，动画速度被修改（`SyncAttackSpeed()` 改变 `animator.speed`）后，帧号和实际挥刀时机就不再对应。Animation Event 天然跟随动画时间轴，不受速度缩放影响。

### 2.2 攻击与受击分离：IDamagable 接口

攻击方通过 `IDamagable` 接口调用目标，不关心目标是玩家、敌人还是宝箱：

```csharp
// Interface/IDamagable.cs:3
public interface IDamagable
{
    public bool TakeDamage(float damage, float elementalDamage, ElementType element, Transform transform);
}
```

`Entity_Combat.PerformAttack()` 遍历检测到的 Collider，用 `GetComponentInParent<IDamagable>()` 找接口，找到了就能打。这使得**技能物体、投射物、范围攻击——所有能造成伤害的东西——都可以用完全相同的代码路径**。

### 2.3 伤害数据的"一次性打包"：AttackData

`AttackData` 在构造函数中一次性完成所有计算：

```csharp
// Data/DamageData/AttackData.cs:15-18
public AttackData(Entity_Stats entityStats, DamageScaleData scaleData)
{
    physicalDamage = entityStats.GetPhyiscalDamage(out isCrit, scaleData.phsycal);
    elementDamage = entityStats.GetElementDamage(out element, scaleData.elemental);
    effectData = new ElementalEffectData(entityStats, scaleData);
}
```

好处：攻击方在这一帧统一算好所有数据，后续的 `TakeDamage` → 护甲减伤 → 抗性减免 → 状态效果施加全部使用同一份"快照"数据。不会出现"攻击时攻击力是 100，打中时变成了 90"的不一致。

### 2.4 普攻走状态机，技能走独立系统

基本攻击通过状态机管理（`Player_BasicAttackState`、`Enemy_AttackState`），而技能（Dash/SwordThrow/TimeEcho）有独立的 `Skill_Base` 继承体系。两个系统共享底层的 `Entity_Combat.PerformAttack()` 和 `IDamagable`，但触发方式不同：

| 攻击类型 | 触发方式 | 管理方式 |
|---------|---------|---------|
| 基本攻击/连招 | Animation Event → `AttackTrigger()` | 状态机状态 |
| 敌人攻击 | Animation Event → `AttackTrigger()` | 状态机状态 |
| 技能伤害 | 技能组件直接调用 `PerformAttack()` | 技能系统 |
| 投射物 | `OnTriggerEnter2D` → `PerformAttackOnTarget()` | 投射物自身 |
| 反击 | `Enter()` 中直接调用 `CounterAttackPerformed()` | 状态机状态 |

| `Entity_VFX` | MonoBehaviour | 命中/受击/状态 VFX | `CreateOnHitVFX()`, `PlayOnDamageVFX()`, `PlayOnStatusVfx()` | 被 `Entity_Combat`、`Entity_Health`、`Entity_StatusHandler` 调用 |

## 5. 运行流程——时序详解

### 5.1 玩家连招攻击完整时序

```
T=0ms    玩家按 J（Attack 键）
         PlayerState.Update() → input.Player.Attack.WasPressedThisFrame()=true
         但当前状态是 Idle，不是在 BasicAttackState 里
         → 需要另一个入口来触发第一次攻击

T=16ms   Player.IdleState/GroundedState 等各状态的 Update 中
         检测到 Attack 输入，调用 stateMachine.ChangeState(basicAttackState)
         注意：不是 PlayerState.Update() 里的检测（那是连招排队用的），
         而是具体的 Idle/Move/Jump 等子状态各自检测攻击键

T=16ms   Player_BasicAttackState.Enter()
         ├─ comboAttackQueued = false
         ├─ ResetComboIndexIfNeeded()
         │   └─ Time.time > lastTimeAttacked + comboResetTime?
         │       是 → comboIndex = 1 (重开一轮连招)
         │       否 → 继续当前 comboIndex
         ├─ SyncAttackSpeed() → anim.SetFloat("attackSpeedMultiplier", ...)
         ├─ anim.SetInteger("basicAttackIndex", comboIndex)
         │   → Animator 根据参数跳转到第 N 段攻击动画
         └─ ApplyAttackVelocity() → 攻击带位移

T=50ms   动画播放中，武器逐渐挥出

T=200ms  ★ Animation Event: "AttackTrigger()"  ← 武器命中帧
         Entity_AnimationTriggers.AttackTrigger()
         → entityCombat.PerformAttack()
         → OverlapCircleAll → 发现目标 → TakeDamage → 结算

T=250ms  玩家按 J（想连招）
         Player_BasicAttackState.Update()
         → input.Player.Attack.WasPressedThisFrame() = true
         → QueueNextAttack()
         → comboIndex(1) < comboLimit(3)? → comboAttackQueued = true

T=400ms  ★ Animation Event: "CurrentStateTrigger()"  ← 攻击动画最后一帧
         → entity.CurrentStateAnimationTrigger()
         → stateMachine.currentSate.AnimationTrigger()
         → triggerCalled = true

T=400ms  Player_BasicAttackState.Update() 同一帧内检测到 triggerCalled=true
         → HandleStateExit()
         → comboAttackQueued == true?
             是 → anim.SetBool(animBoolName, false)  ← 取消剩余动画
                 player.EnterAttaclStateWithDelay()   ← 延迟一帧进入下一段
             否 → stateMachine.ChangeState(player.idleState)

T=400ms  Exit() → comboIndex++ (comboIndex 从 1 变成 2)

T=416ms  协程 EnterAttackStateWithDelayCo 一帧后触发
         → stateMachine.ChangeState(basicAttackState) ← 进入第二段连招

T=416ms  Player_BasicAttackState.Enter() 再次进入
         → comboIndex 已经是 2，播放第二段攻击动画
         → 重复上述流程直到 comboIndex=3 打完

T=1200ms 如果玩家不再按键，第三段打完 triggerCalled → comboAttackQueued=false
         → stateMachine.ChangeState(idleState)
```

### 5.2 敌人受伤→进入战斗的时序

```
T=0ms    敌人在 Enemy_IdleState 或 Enemy_MoveState 中闲逛

T=100ms  玩家靠近，攻击命中敌人
```

## 6. 关键实现细节

### 6.1 攻击检测：`Physics2D.OverlapCircleAll`

```csharp
// Entity_Combat.cs:164-186
protected Collider2D[] GetDectedColliders(LayerMask whatToDetect)
{
    return Physics2D.OverlapCircleAll(
        targetCheck.position,      // 检测圆心（角色前方某点）
        targetCheckRadius,         // 检测半径
        whatToDetect               // LayerMask 过滤
    );
}
```

**Unity 配置要点：**
- `targetCheck` — 角色子物体上的空 Transform，放在武器前方位置。需要在 Inspector 拖拽赋值，不能在代码里 `new Transform()`
- `targetCheckRadius` — 在 Inspector 中配置，`OnDrawGizmos()` 画出线框方便调参
- `whatIsTarget` — LayerMask，在 Inspector 中选择。玩家攻击检测 "Enemy" 层，敌人攻击检测 "Player" 层
- 选择 `OverlapCircleAll` 而非 `Raycast`：2D 横版游戏的攻击范围通常是一个面（扇形/圆形），圆形检测容错率高，不容易出现"看着打中了但 Raycast 没穿过"的情况

**一个容易忽略的点：** 返回值包含**被禁用的 Collider**。如果敌人死亡时 Collider 被设为 `enabled=false` 但还没销毁，`OverlapCircleAll` 仍会检测到它。项目没有显式处理这种情况，但 `TakeDamage` 里 `isDead` 判断会直接 `return false`，所以不会造成重复击杀。

### 6.2 Animation Event 桥接层

Animation Event 是 Unity 的机制——它在指定帧调用 GameObject 上的 public 方法，**但不能传自定义参数（除了少数基础类型）**。

项目用了一个分层桥接设计：

```
Animation Event 调用 (挂在角色 Animator 所在 GameObject 的子物体上)
    │
    ▼
Entity_AnimationTriggers.AttackTrigger()       ← public, 无参数
    │
    ▼
entityCombat.PerformAttack()                   ← 执行攻击逻辑
```

```
Animation Event 调用
    │
    ▼
Entity_AnimationTriggers.CurrentStateTrigger()  ← public, 无参数
    │
    ▼
entity.CurrentStateAnimationTrigger()           ← Entity.cs 的方法
    │
    ▼
stateMachine.currentSate.AnimationTrigger()     ← EntityState.cs:43
    │
    ▼
triggerCalled = true                            ← 状态机状态里的 bool
```

**设计要点：**
- `Entity_AnimationTriggers` 挂在角色根物体的**子物体**上（不是角色自身），因为 Animation Event 只能调用**挂载 Animator 的 GameObject 及其子物体**上的方法
- `CurrentStateTrigger()` 通过 `Entity → StateMachine → currentState` 的引用链把事件传递给当前活动状态，实现了"动画驱动状态切换"的通用桥接
- 子类 `Enemy_AnimationTriggers` 扩展了 `EnableCounterWindow(bool)` —— 在攻击动画的特定帧（前摇结束到命中之间）打开反击窗口，命中帧或后摇帧关闭。这是通过两个 Animation Event 实现的

### 6.3 连招系统：`comboAttackQueued` + 延迟一帧入状态

```csharp
// Player_BasicAttackState.cs
public override void Update()
{
    if (input.Player.Attack.WasPressedThisFrame())  // 攻击键按下
        QueueNextAttack();                          // 只标记，不立刻切换

    if (triggerCalled)                              // 动画播放完毕
        HandleStateExit();                          // 决定下一状态
}

private void QueueNextAttack()
{
    if (comboIndex < comboLimit)          // 还有下一段?
        comboAttackQueued = true;         // 排队等候
}

private void HandleStateExit()
{
    if (comboAttackQueued)
    {
        anim.SetBool(animBoolName, false);   // 取消剩余动画
        player.EnterAttaclStateWithDelay();   // ★ 延迟一帧
    }
    else
        stateMachine.ChangeState(player.idleState);
}
```

**延迟一帧的原因（代码注释中的解释）：**

```csharp
// Player.cs:160-167
public void EnterAttaclStateWithDelay()
{
    if (queueAttackCo != null)
        StopCoroutine(queueAttackCo);
    queueAttackCo = StartCoroutine(EnterAttackStateWithDelayCo());
}

private IEnumerator EnterAttackStateWithDelayCo()
{
    yield return null;                    // ★ 等一帧
    stateMachine.ChangeState(basicAttackState);
}
```

为什么需要延迟一帧？因为 `HandleStateExit()` 在 Animation Event 的回调中执行——此时代码和 Animator 状态更新在**同一帧**内。如果直接 `ChangeState(basicAttackState)`，Animator 会有"同一帧内 SetBool(false) 又 SetBool(true)"的冲突——动画的 Exit Time / Transition 条件可能还没处理完就又被覆盖了。延迟一帧让当前状态的 Exit 完成（`anim.SetBool(animBoolName, false)` 生效），下一帧再干净地 Enter 新状态。

### 6.4 连招重置窗口

```csharp
// Player_BasicAttackState.cs:98-107
private void ResetComboIndexIfNeeded()
{
    if(Time.time > player.comboResetTime + lastTimeAttacked)
        comboIndex = FirstComboIndex;   // 间隔太久，重开连招
```

`comboResetTime` 默认 1 秒，在 `Player` 的 Inspector 中配置。这是动作游戏的标配设计——如果玩家停手超过一段时间，连招从头开始。

### 6.5 攻击速度同步

```csharp
// EntityState.cs:53-57
public void SyncAttackSpeed()
{
    float attackSpeed = stats.offense.attackSpeed.GetValue();
    anim.SetFloat("attackSpeedMultiplier", attackSpeed);
}
```

攻击速度通过 Animator 的 Float 参数 `attackSpeedMultiplier` 控制动画播放速度。**这里不是直接 `anim.speed = attackSpeed`**（那会影响所有动画），而是通过 Animator Controller 里每个攻击 State 的 `Speed` 属性乘以这个 Float 参数——只影响攻击动画，不影响移动和待机。

装备上如果有 +20% 攻击速度的 modifier，`attackSpeed.GetValue()` 返回 1.2，攻击动画快 20%。

### 6.6 伤害计算公式（硬编码在 Entity_Stats 中）

| 公式 | 代码位置 | 说明 |
|------|---------|------|
| 基础伤害 = `damage + strength` | `Entity_Stats:125` | 攻击力 + 力量 |
| 暴击率 = `critChance + agility*0.3` | `Entity_Stats:126` | 暴击 + 敏捷×0.3 |
| 暴击倍率 = `(critPower + strength*0.5) / 100` | `Entity_Stats:127` | 暴击伤害 + 力量×0.5 |
| 护甲减伤 = `armor/(armor+100)` 上限 85% | `Entity_Stats:129-143` | LOL 标准公式 |
| 闪避 = `evasion + agility*0.5` 上限 70% | `Entity_Stats:154-164` | 闪避 + 敏捷×0.5 |
| 最大生命 = `maxHealth + vitality*5` | `Entity_Stats:166-172` | 基础生命 + 活力×5 |
| 元素抗性 = `res + intelligence*0.5` 上限 75% | `Entity_Stats:85-109` | 对应抗性 + 智力×0.5 |
| 元素伤害 = `max(火,冰,雷) + 其余×0.5 + intelligence` | `Entity_Stats:46-83` | 主元素全取 + 副元素各 50% |

### 6.7 护甲减伤公式深入理解

`armor / (armor + 100)` —— 每一点护甲收益递减：

| 护甲值 | 减伤率 | 等效生命倍率 |
|--------|--------|------------|
| 0 | 0% | 1.0× |
| 50 | 33% | 1.5× |
| 100 | 50% | 2.0× |
| 200 | 66% | 3.0× |
| 300 | 75% | 4.0× |
| 400 | 80% | 5.0× |

等效生命 = `HP / (1-减伤率)`。护甲从 0 到 100 给了 2× 等效生命，从 100 到 200 给了 1.5×。收益递减但**每点护甲的等效生命增量是线性的**——这就是这个公式的精妙之处。

### 6.8 穿甲计算

```csharp
// Entity_Stats.cs:129-143
public float GetArmorMitigation(float armorReduction)
{
    float totalArmor = GetBaseArmor();              // armor + vitality
    float reductionMultiplier = Mathf.Clamp(1 - armorReduction, 0, 1);
    float effectiveArmor = totalArmor * reductionMultiplier;
    float mitigation = effectiveArmor / (effectiveArmor + 100);
    return Mathf.Clamp(mitigation, 0, 0.85f);
}
```

`armorReduction` 来自攻击方的 `offense.armorReduction.GetValue() / 100`（见 `Entity_Stats:148-152`），会被 `TakeDamage` 传入。穿甲是**先减再算**——100 护甲 + 30% 穿甲 = 70 有效护甲 = 41% 减伤（原本 50%）。

```
1. 敌人进入 AttackState
```

### 6.13 敌人受击→进入战斗的连锁反应

```csharp

{
    if(canTakenDamage == false)
        return false;

    bool wasHit = base.TakeDamage(...);  // 先结算伤害

        return false;

    // 只有玩家打的才算（防止敌人误伤触发战斗）
```

注意 `base.TakeDamage()` 先执行——如果被闪避了，返回值是 `false`，就不会进入战斗。这个时序很重要：**闪避掉的攻击不会拉仇恨**。

### 6.14 投射物的弹道计算（法师敌人）

```csharp
// Enemy_MageProjectile.cs:46-74
private Vector2 CalculateBallisticVelocity(Vector2 start, Vector2 end)
{
    float gravity = Mathf.Abs(Physics2D.gravity.y * rb.gravityScale);
    float displacementY = end.y - start.y;
    float displacementX = end.x - start.x;
    float peakHeight = Mathf.Max(arcHeight, end.y - start.y + 0.1f);
    float timeToApex = Mathf.Sqrt(2 * peakHeight / gravity);
    float timeFromApex = Mathf.Sqrt(2 * (peakHeight - displacementY) / gravity);
    float totalTime = timeToApex + timeFromApex;
    float velocityY = Mathf.Sqrt(2 * gravity * peakHeight);
    float velocityX = displacementX / totalTime;
    return new Vector2(velocityX, velocityY);
}
```

这是标准的**弹道学抛物线公式**——给定起点和终点，计算出初速度让投射物恰好沿弧线飞抵目标。不是简单的 `transform.Translate` 或固定的 `rb.velocity`，而是物理驱动的真实抛物线。`arcHeight` 控制弧线高度。

## 7. 优化手段

### 7.1 状态构造时一次性 new（零 GC）

```csharp
// Enemy_Skeleton.cs:Awake
idleState = new Enemy_IdleState(this, stateMachine, "idle");
moveState = new Enemy_MoveState(this, stateMachine, "move");
attackState = new Enemy_AttackState(this, stateMachine, "attack");
// ...
```

所有状态在 `Awake()` 中创建，整个生命周期只 new 一次。状态切换时只切换引用而不创建新实例——避免了 GC spike 影响战斗流畅度。

### 7.2 GetComponent 全在 Awake 中缓存

每个组件的 `Awake()` 中把所有需要的组件引用一次性获取并缓存到字段中。战斗中（`Update`、`PerformAttack`、`TakeDamage`）没有任何 `GetComponent` 调用。

### 7.3 AttackData 是纯 C# struct-like class

`AttackData` 不用 MonoBehaviour，直接 new 出来传参。用完即弃，不占 GameObject 开销。虽然有 GC，但每次攻击只创建一次，频率低。

### 7.4 脏标记减少属性查询

战斗系统中每次攻击都读多个属性值（damage, critChance, strength 等），这些读取全部通过 `Stat.GetValue()` —— 脏标记保证只在属性实际改变时才重新遍历 modifiers，战斗中 99.9% 的读取是 O(1) 缓存命中。详见 `stat的脏标记设计.md`。

## 8. 与 Unity 自带系统的关系

| 功能 | Unity 自带方案 | 项目实际做法 | 选择理由 |
|------|-------------|------------|---------|
| 攻击判定时机 | `Animation Event` | 使用 | 与动画精确同步，不受速度缩放影响 |
| 攻击范围检测 | `Physics2D.OverlapCircleAll` | 使用 | 实现简单、容错高 |
| 状态机 | `Animator Controller` 的 State/Transition | **自定义 C# StateMachine** | 需要逻辑层状态机做决策（攻速、冷却、连招排队），Animator 只管表现 |
| 伤害公式 | — | 硬编码在 `Entity_Stats` | 公式简单稳定，不需要 SO 配置 |
| 数值配置 | 直接序列化在 Inspector | `DamageScaleData` 可序列化类 | 每种攻击可以有不同的缩放系数 |
| 技能效果 | — | 自定义 `Skill_Base` 继承体系 | 需要 CD、升级、多种武器变体等复杂逻辑 |

## 10. 易混淆点 FAQ

**Q1: 为什么 `PerformAttack()` 用 `GetComponentInParent<IDamagable>()` 而不是 `GetComponent<IDamagable>()`？**

因为检测到的 Collider 可能在目标物体的子物体上（比如碰撞盒是子物体），而 `IDamagable` 接口通常挂在根物体（Entity_Health 在 Entity 身上）。`GetComponentInParent` 沿着层级向上找，兼容更广。

**Q2: 连招为什么要"延迟一帧进入下一状态"？**

Animation Event `CurrentStateTrigger()` 触发时，当前帧的 Animator 状态更新还未完成。如果直接 `ChangeState(basicAttackState)` → `anim.SetBool("basicAttack", true)`，会和同一帧即将发生的 `Exit()` → `anim.SetBool("basicAttack", false)` 产生竞争。延迟一帧确保当前状态先完全退出。

**Q3: 闪避判定 vs 护甲减伤，哪个先？**

```
TakeDamage → AttackEvaded() 先判断 → 闪避成功直接 return false (完全免伤)
          → 未闪避 → 计算护甲减伤 + 元素抗性
```

闪避优先。闪避是"完全免伤"，护甲是"百分比减伤"。

**Q4: 为什么元素伤害取最高值而不是相加？**

鼓励玩家专注培养一种元素流派。如果火/冰/雷直接相加，堆三种元素的收益是三倍，平衡性难控制。当前设计是"主元素 100% + 其他各 50%"，选择专注一种（例如全堆火）比平均分配收益更高。

**Q5: 反击窗口的时间是怎么确定的？**

完全由 Animation Event 决定。`EnableCounterWindow()` 和 `DisableCounterWindow()` 分别挂在敌人攻击动画的特定帧上——通常在前摇结束后（武器开始发光）到命中帧前关闭。这个时间不是代码计算的，而是美术/设计师在动画编辑器中确定的。

**Q6: 灼烧伤害为什么直接 `ReduceHealth` 而不走 `TakeDamage`？**

灼烧是 DOT 效果，不存在"闪避灼烧"的概念。直接调 `ReduceHealth()` 跳过护甲/闪避的二次计算。但灼烧的总伤害量在 `ApplyBurnEffect` 中会先经过火抗减免。

**Q7: 多个敌人同时被打中，每个的计算都是独立的吗？**

是的。`AttackData` 在 `foreach` 循环**内**创建（`Entity_Combat.cs:45`），每个目标调用一次 `stats.GetAttackData(basicAttackScale)`。这意味着每个敌人有**独立的暴击掷骰**——一刀挥出去，三个敌人可能一个暴击、两个没暴击。元素伤害不受随机影响，所以各目标拿到的元素伤害值相同。如果你期望"一刀暴击全暴击"的效果，需要把 `AttackData` 的创建提到循环外面。

**Q8: 玩家和敌人共享同一套 `TakeDamage` 逻辑吗？**

是的。`Entity_Health.TakeDamage()` 是基类实现，包含闪避/护甲/抗性/击退的完整流程。`Player_Health` 只覆盖了 `Die()`，`Enemy_Health` 覆盖了 `TakeDamage()` 来追加"受伤后进入战斗"的逻辑（但先调用的 `base.TakeDamage()`），`Enemy_Health` 还有一个关键覆盖——`canTakenDamage` 判断放在 `base.TakeDamage()` **之前**，防止无敌状态下被触发战斗。

**Q9: 攻击位移和移动速度会叠加吗？**

会。`ApplyAttackVelocity()` 中 `player.SetVelocity(attackVelocity.x * attackDir, attackVelocity.y)` 直接设置了 Rigidbody2D 的速度。如果同时有其他系统也在设置速度（如击退协程），后设置者覆盖前者。`attackVelocityTimer` 超时后水平速度归零，但垂直速度保留（因为是 `rb.linearVelocity.y`），所以连招中如果跳起会保持 Y 轴速度。

**Q10: 元素效果为什么用协程而不是用 Update 中的 timer？**

协程更简洁——启动 → `yield return new WaitForSeconds(duration)` → 清理。不需要在 `Update` 中每帧检查 timer。但代价是协程依赖 MonoBehaviour 的生命周期——如果角色在效果持续期间被销毁，协程也会终止（这是预期的行为）。

## 11. 如何迁移到自己的项目

### 可直接复用

- `IDamagable` 接口 —— 任何需要"受伤"的系统都可以用
- `AttackData` 快照模式 —— 一次计算、多次使用的伤害数据结构
- Animation Event → `PerformAttack()` 的桥接模式 —— 通用且可靠
- `Entity_Combat.PerformAttack()` 的检测→结算→反馈流程

### 需要改造

- `DamageScaleData` 和 `Entity_Stats` 是紧密耦合的——需要替换成你自己的属性系统
- 护甲/闪避/抗性公式硬编码在 `Entity_Stats` 中——如果你的公式不同需要重写
- 状态机系统是自定义的——如果你的项目用 Unity Animator Controller 做状态管理，需要适配

### Unity 编辑器中要重新配置

- **LayerMask**: `whatIsTarget`、`whatIsCounterable` 需要在 Inspector 中指定你项目里的层
- **Animation Event**: 每个攻击动画的 Clip 中需要手动添加 `AttackTrigger()` 和 `CurrentStateTrigger()` 事件
- **targetCheck Transform**: 需要创建子物体并拖拽到 `Entity_Combat` 的 Inspector 字段
- **反击窗口 VFX**: `Enemy_AnimationTriggers` 中的 `EnableCounterWindow` 需要配置 VFX 预制体

### 迁移后最容易出的错

1. Animation Event 挂了但方法名拼写不一致（Unity 不报错，只是静默不触发）
2. `whatIsTarget` LayerMask 选错，导致检测不到目标或误伤友军
3. `targetCheckRadius` 设太小导致打不中人
4. 忘记给敌人 Prefab 挂 `ICounterable` 实现，反击系统无效

## 12. 总结

**战斗系统的本质：Animation Event 驱动攻击判定 + IDamagable 解耦攻防 + AttackData 一次性打包伤害 + Entity_Health 统一结算 + Entity_StatusHandler 附加元素效果。**

**最重要的类：**
- `Entity_Combat` — 攻击发起方，串联检测→计算→结算→反馈
- `Entity_Health` — 受击方，统一处理闪避/护甲/抗性/减伤
- `AttackData` — 伤害快照，一次性计算避免不一致
- `Entity_AnimationTriggers` — 动画到逻辑的桥接层

**核心流程一句话：** 动画事件在精确帧触发 → `OverlapCircleAll` 检测目标 → `IDamagable.TakeDamage()` 统一结算 → 属性系统提供数值 → VFX/SFX/元素效果/击退做反馈。

**最该学到的东西：**

1. **Animation Event 做攻击判定是动作游戏的标配**——它天然跟随动画时间轴，不受 `anim.speed` 缩放影响，比代码计时可靠得多
2. **IDamagable 接口让"谁被打"和"打了谁"完全解耦**——同一个 `PerformAttack()` 可以打玩家、敌人、宝箱、技能物体，分别有不同的受击行为
3. **AttackData 快照模式避免了属性不一致**——攻击瞬间锁死所有伤害值，后续无论属性怎么变都不影响本次伤害
4. **连招的"排队+延迟一帧"是纯代码状态机和 Animator 协同工作的经典模式**——解决了动画过渡和代码状态切换之间的时序竞争
