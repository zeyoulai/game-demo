# 战斗系统深度分析_主程讲解版

> 分析对象：`Udemy-Course-RPG` 的 2D RPG 战斗系统  
> 阅读方式：先看第 2、3、4 节建立全局图，再看第 6 节理解每条战斗链路，最后用第 10、11 节排坑和迁移。

## 1. 系统定位：战斗系统到底解决什么问题

这个项目的战斗系统不是一个单独的“扣血函数”，而是一条由多个系统拼起来的管线：

```text
输入/AI 决策
  -> 状态机进入攻击状态
  -> Animator 播放对应动画
  -> Animation Event 在命中帧触发
  -> Combat 检测目标并组装 AttackData
  -> IDamagable.TakeDamage 结算闪避/护甲/抗性/扣血/击退
  -> Status/VFX/SFX/装备效果响应本次命中
```

它解决的是动作 RPG 里最容易混在一起的四件事：

| 问题 | 本项目怎么拆 |
| --- | --- |
| 什么时候造成伤害 | Animation Event 调 `AttackTrigger()` |
| 打到谁 | `Physics2D.OverlapCircleAll` + `LayerMask` |
| 打多少 | `Entity_Stats.GetAttackData(DamageScaleData)` |
| 被打后怎么办 | `IDamagable.TakeDamage(...)` 由目标自己实现 |

初学者常见写法是把输入、动画、碰撞、扣血、特效全写在 `Update()` 或玩家脚本里。这个项目的聪明点在于：攻击者只负责“发起一次攻击判定”，受击者自己决定如何承受伤害，属性系统负责产出数值，动画系统负责给出命中时机。

## 2. 一句话总览

**这个战斗系统的本质是：Animation Event 驱动的命中判定 + Interface 解耦的受击结算 + Stat 快照生成的伤害数据。**

核心调用链：

```text
Player_GroundedState / Enemy_BattleState
  -> Player_BasicAttackState / Enemy_AttackState
  -> SyncAttackSpeed()
  -> Animator 播放攻击动画
  -> Animation Event: AttackTrigger()
  -> Entity_AnimationTriggers.AttackTrigger()
  -> Entity_Combat.PerformAttack()
  -> Physics2D.OverlapCircleAll(...)
  -> target.GetComponentInParent<IDamagable>()
  -> Entity_Stats.GetAttackData(...)
  -> IDamagable.TakeDamage(...)
  -> Entity_StatusHandler.ApplyStausEffect(...)
  -> VFX/SFX/OnDoingPhysicalDamage
```

- `AttackTrigger()` 转发到 Combat：`Assets/Scripts/Entity/Entity_AnimationTriggers.cs:21`

## 5. 为什么这样设计

### 5.1 为什么伤害判定放在 Animation Event

攻击是否命中，玩家感知上不是“按键后的第 0.3 秒”，而是“刀挥到敌人身体的那一帧”。所以本项目把 `AttackTrigger()` 放在动画 Clip 的命中帧上。

例如玩家三段普攻：

| 动画 | 命中事件 | 结束事件 |
| --- | --- | --- |
| `PlayerBasicAttack_1.anim` | `AttackTrigger` at `0.35714287`，`Assets/Animations/Player/PlayerBasicAttack_1.anim:97` | `CurrentStateTrigger` at `0.5714286`，`Assets/Animations/Player/PlayerBasicAttack_1.anim:104` |
| `PlayerBasicAttack_2.anim` | `AttackTrigger` at `0.083333336`，`Assets/Animations/Player/PlayerBasicAttack_2.anim:82` | `CurrentStateTrigger` at `0.25`，`Assets/Animations/Player/PlayerBasicAttack_2.anim:89` |
| `PlayerBasicAttack_3.anim` | `AttackTrigger` at `0.14285715`，`Assets/Animations/Player/PlayerBasicAttack_3.anim:97` | `CurrentStateTrigger` at `0.5714286`，`Assets/Animations/Player/PlayerBasicAttack_3.anim:104` |

注意一个容易说错的点：`SyncAttackSpeed()` 不是直接改 `animator.speed`，而是：

```csharp
// Assets/Scripts/StateMachine/EntityState.cs:53
anim.SetFloat("attackSpeedMultiplier", attackSpeed);
```

Animator Controller 中攻击状态把 `attackSpeedMultiplier` 配成速度参数，例如玩家 Controller 里有 `m_SpeedParameter: attackSpeedMultiplier`，见 `Assets/Animations/AnimatoerControllers/Characters/Player.controller:602`。

所以准确说法不是“Animation Event 不受速度缩放影响”，而是：**事件绑定在动画时间轴上，速度参数改变后，事件会跟着动画姿态一起提前或延后，仍然对齐挥刀动作。**

### 5.2 为什么用 `IDamagable` 而不是 Tag

`Entity_Combat.PerformAttack()` 找的是接口：

```csharp
// Assets/Scripts/Entity/Entity_Combat.cs:35
IDamagable damagable = target.GetComponentInParent<IDamagable>();
```

这意味着攻击系统不关心目标是玩家、敌人、宝箱还是技能物体，只要它实现了 `IDamagable`，就能被打。比如宝箱 `Object_Chest` 也实现了 `IDamagable`，所以“攻击开箱”不需要在 Combat 里写特殊判断。

Tag 只能回答“它叫什么”，接口能回答“它能做什么”。战斗系统真正需要的是后者。

### 5.3 为什么要 `DamageScaleData -> AttackData`

`DamageScaleData` 是配置：这次攻击物理倍率多少、元素倍率多少、灼烧倍率多少。

`AttackData` 是运行时快照：在攻击发生的一瞬间，把当前属性、暴击、元素类型、异常数据算出来。

```text
DamageScaleData
  -> Entity_Stats.GetAttackData(scale)
  -> new AttackData(entityStats, scale)
  -> physicalDamage / elementDamage / isCrit / element / effectData
```

这样做的好处是：普攻、技能、分身攻击都可以复用同一套数值公式，只换倍率配置。

## 6. 运行流程详解

### 6.1 玩家普通攻击

入口在地面状态：

```csharp
// Assets/Scripts/Player/PlayerStates/Player_GroundedState.cs:22
if (input.Player.Attack.WasPressedThisFrame())
    stateMachine.ChangeState(player.basicAttackState);
```

进入普攻状态后做四件事：

1. 重置/判断连段：`ResetComboIndexIfNeeded()`。
2. 同步攻击速度：`SyncAttackSpeed()`。
3. 设置 Animator 的 `basicAttackIndex`。
4. 根据当前输入或朝向施加一次攻击位移。

关键代码：

```csharp
// Assets/Scripts/Player/PlayerStates/Player_BasicAttackState.cs:21
public override void Enter()
{
    base.Enter();
    comboAttackQueued = false;
    ResetComboIndexIfNeeded();
    SyncAttackSpeed();

    attackDir = player.moveInput.x != 0 ? ((int)player.moveInput.x) : player.facingDir;
    anim.SetInteger("basicAttackIndex", comboIndex);
    ApplyAttackVelocity();
}
```

普攻状态的 `Update()` 不直接扣血，只监听两件事：

- 玩家是否再次按攻击：设置 `comboAttackQueued`。
- 动画是否通过 `CurrentStateTrigger()` 通知状态结束：`triggerCalled == true`。

```csharp
// Assets/Scripts/Player/PlayerStates/Player_BasicAttackState.cs:40
if (input.Player.Attack.WasPressedThisFrame())
    QueueNextAttack();

// Assets/Scripts/Player/PlayerStates/Player_BasicAttackState.cs:43
if (triggerCalled)
    HandleStateExit();
```

这里的设计有一点很动作游戏：输入缓冲不是立刻切状态，而是先记录 `comboAttackQueued`，等当前动画走到允许结束的事件点，再进入下一段。这避免了玩家快速点击导致动画被硬切得很碎。

### 6.2 Animation Event 到 Combat

动画事件不会直接访问状态类，而是先打到一个桥接组件：

```csharp
// Assets/Scripts/Entity/Entity_AnimationTriggers.cs:21
private void AttackTrigger()
{
    entityCombat.PerformAttack();
}
```

动画结束事件则走：

```csharp
// Assets/Scripts/Entity/Entity_AnimationTriggers.cs:15
private void CurrentStateTrigger()
{
    entity.CurrentStateAnimationTrigger();
}
```

这个桥接层的价值是：动画 Clip 只需要知道“我要触发一个名字叫 AttackTrigger 的方法”，不用知道状态机、Combat、Stats 的内部结构。

### 6.3 `Entity_Combat.PerformAttack()` 的完整链路

`PerformAttack()` 是近战攻击的核心：

```text
PerformAttack()
  -> GetDectedColliders(whatIsTarget)
  -> foreach collider
  -> GetComponentInParent<IDamagable>()
  -> stats.GetAttackData(basicAttackScale)
  -> target.GetComponentInParent<Entity_StatusHandler>()
  -> damagable.TakeDamage(...)
  -> 如果有元素：ApplyStausEffect(...)
  -> 如果真的命中：VFX/SFX/OnDoingPhysicalDamage
  -> 如果一个都没命中：PlayAttackMiss()
```

对应代码：

```csharp
// Assets/Scripts/Entity/Entity_Combat.cs:31
foreach (var target in GetDectedColliders(whatIsTarget))
{
    IDamagable damagable = target.GetComponentInParent<IDamagable>();
    if (damagable == null)
        continue;

    AttackData attackData = stats.GetAttackData(basicAttackScale);
    Entity_StatusHandler statusHandler = target.GetComponentInParent<Entity_StatusHandler>();

    bool targetGotHit = damagable.TakeDamage(
        attackData.physicalDamage,
        attackData.elementDamage,
        attackData.element,
        transform
    );
}
```

检测范围来自 Inspector 配置：

```csharp
// Assets/Scripts/Entity/Entity_Combat.cs:14
[SerializeField] private Transform targetCheck;
[SerializeField] private float targetCheckRadius;
[SerializeField] private LayerMask whatIsTarget;
```

真正检测：

```csharp
// Assets/Scripts/Entity/Entity_Combat.cs:167
Collider2D[] colliders = Physics2D.OverlapCircleAll(
    targetCheck.position,
    targetCheckRadius,
    whatToDetect
);
```

这里选择 `OverlapCircleAll` 而不是武器 Collider 常驻触发，有一个非常明确的取舍：只在命中帧检测一次，命中窗口清晰；代价是每次调用会分配数组，后期可用 `OverlapCircleNonAlloc` 优化。

### 6.4 伤害数据怎么算

`Entity_Stats.GetAttackData()` 很薄：

```csharp
// Assets/Scripts/Entity/Entity_Stats.cs:41
public AttackData GetAttackData(DamageScaleData scaleData)
{
    return new AttackData(this, scaleData);
}
```

真正的快照在 `AttackData` 构造函数：

```csharp
// Assets/Scripts/Data/DamageData/AttackData.cs:15
public AttackData(Entity_Stats entityStats, DamageScaleData scaleData)
{
    physicalDamage = entityStats.GetPhyiscalDamage(out isCrit, scaleData.phsycal);
    elementDamage = entityStats.GetElementDamage(out element, scaleData.elemental);
    effectData = new ElementalEffectData(entityStats, scaleData);
}
```

物理伤害：

- 基础伤害 = `offense.damage + major.strength`，见 `Assets/Scripts/Entity/Entity_Stats.cs:125`
- 暴击率 = `offense.critChance + agility * 0.3`，见 `Assets/Scripts/Entity/Entity_Stats.cs:126`
- 暴击倍率 = `offense.critPower + strength * 0.5`，见 `Assets/Scripts/Entity/Entity_Stats.cs:127`
- 最终再乘 `DamageScaleData.phsycal`。

元素伤害：

- 火/冰/雷取最高的一个作为主元素。
- 其他较弱元素按 50% 叠加。
- `intelligence` 作为额外元素伤害。
- 最终再乘 `DamageScaleData.elemental`。

这套公式让装备属性和技能倍率自然联动：同一个技能在不同配装下会打出不同元素类型和伤害。

### 6.5 受击结算：`Entity_Health.TakeDamage`

目标侧的 `TakeDamage()` 是防御规则中心：

```csharp
// Assets/Scripts/Entity/Entity_Health.cs:66
public virtual bool TakeDamage(float damage, float elementalDamage, ElementType element, Transform damageDealer)
```

结算顺序：

1. 死亡或无敌时直接失败。
2. 先判定闪避。
3. 从攻击者读取破甲。
4. 从受击者读取护甲减伤和元素抗性。
5. 分别计算物理伤害和元素伤害。
6. 根据物理伤害大小决定击退力度。
7. 扣血、记录 `lastDamageTaken`、触发 `OnTakingDamage`。

关键代码：

```csharp
// Assets/Scripts/Entity/Entity_Health.cs:70
if (AttackEvaded())
    return false;

// Assets/Scripts/Entity/Entity_Health.cs:76
Entity_Stats attackStates = damageDealer.GetComponent<Entity_Stats>();
float armorReduction = attackStates != null ? attackStates.GetArmorReduction() : 0;

// Assets/Scripts/Entity/Entity_Health.cs:79
float mitigation = entityStats != null ? entityStats.GetArmorMitigation(armorReduction) : 0;
float resistance = entityStats != null ? entityStats.GetElementalResistance(element) : 0;

// Assets/Scripts/Entity/Entity_Health.cs:82
float physicalDamageTaken = damage * (1 - mitigation);
float elementalDamageTaken = elementalDamage * (1 - resistance);
```

减伤公式：

```text
effectiveArmor = (defense.armor + vitality) * clamp(1 - armorReduction, 0, 1)
mitigation = effectiveArmor / (effectiveArmor + 100)
cap = 85%
```

代码在 `Assets/Scripts/Entity/Entity_Stats.cs:129`。

闪避上限是 70%：

```csharp
// Assets/Scripts/Entity/Entity_Stats.cs:154
float finalEvasion = Mathf.Clamp(totalEvasion, 0, evasionMax);
```

元素抗性上限是 75%，见 `Assets/Scripts/Entity/Entity_Stats.cs:85`。

### 6.6 元素异常：冰、火、雷

`Entity_StatusHandler.ApplyStausEffect()` 根据本次攻击的元素类型进入不同分支：

```csharp
// Assets/Scripts/Entity/Entity_StatusHandler.cs:34
public void ApplyStausEffect(ElementType element, ElementalEffectData effectData)
```

三种异常：

| 元素 | 效果 | 关键实现 |
| --- | --- | --- |
| Ice | 减速一段时间 | `entity.SlowDownEntity(duration, slowMultiplier)`，`Assets/Scripts/Entity/Entity_StatusHandler.cs:130` |
| Fire | 持续伤害 | 每秒 2 tick，`Assets/Scripts/Entity/Entity_StatusHandler.cs:106` |
| Lightning | 累积电荷，满了触发雷击 | `currentCharge >= maximumCharge`，`Assets/Scripts/Entity/Entity_StatusHandler.cs:57` |

这里最值得学的是雷电效果：它不是每次命中都直接爆，而是用 `currentCharge` 做累积条。这已经不是简单的“附加伤害”，而是一个小型状态机。

不过也有坑：`CanBeApplied()` 允许 Lightning 在已有 Lightning 状态时继续叠电荷，但其他元素只能在 `currentEffect == None` 时施加，见 `Assets/Scripts/Entity/Entity_StatusHandler.cs:140`。这意味着冰和火不能互相覆盖，后续如果想做“火融冰”“雷火反应”，这里要重新设计状态共存规则。

### 6.7 反击系统

玩家输入反击：

```csharp
// Assets/Scripts/Player/PlayerStates/Player_GroundedState.cs:28
if (input.Player.CounterAttack.WasPressedThisFrame())
    stateMachine.ChangeState(player.counterAttackState);
```

进入反击状态后，马上做一次反击检测：

```csharp
// Assets/Scripts/Player/PlayerStates/Player_CounterAttackState.cs:16
stateTimer = combat.GetCounterRecoveryDuration();
counteredSomebody = combat.CounterAttackPerformed();
anim.SetBool("counterAttackPerformed", counteredSomebody);
```

`Player_Combat.CounterAttackPerformed()` 使用同一套范围检测，但找的是 `ICounterable`：

```csharp
// Assets/Scripts/Player/Player_Combat.cs:14
foreach (var target in GetDectedColliders(whatIsCounterable))
{
    ICounterable counterable = target.GetComponent<ICounterable>();
    if (counterable == null)
        continue;

    if (counterable.CanBeCountered)
    {
        counterable.HandleCounter();
        hasPerformedCounter = true;
    }
}
```

敌人的可反击窗口由动画事件开关。例如骷髅攻击：

- `EnableCounterWindow` at `0.33333334`，`Assets/Animations/Skeleton/skeletonAttack.anim:124`
- `AttackTrigger` at `0.5833333`，`Assets/Animations/Skeleton/skeletonAttack.anim:131`
- `DisableCounterWindow` at `0.6666667`，`Assets/Animations/Skeleton/skeletonAttack.anim:138`
- `CurrentStateTrigger` at `1.4166666`，`Assets/Animations/Skeleton/skeletonAttack.anim:145`

敌人的桥接代码：

```csharp
// Assets/Scripts/Enemy/Enemy_AnimationTriggers.cs:21
private void EnableCounterWindow()
{
    enemy.EnableCounterWindoow(true);
}
```

这个设计很适合教学：反击窗口不是代码里写死的 0.2 秒，而是贴在敌人攻击动画的前摇和出手帧之间。调手感时，策划/动画只需要移动 Animation Event。

### 6.8 敌人攻击和特殊攻击

```csharp
}
```

例如 ArcherElf 的攻击动画不直接 `AttackTrigger()`，而是在 `0.375` 调 `SpecialAttackTrigger` 发射箭，见 `Assets/Animations/ArcherElf/archerElfAttack.anim:91`。

### 6.9 投射物和定点目标攻击

投射物不走 `OverlapCircleAll`，而是碰撞到目标后调用：

```text
OnTriggerEnter2D
  -> combat.PerformAttackOnTarget(collision.transform)
```

这类路径用在法师 projectile、弓箭、Reaper spell 等。比如 Reaper spell：

```csharp
// Assets/Scripts/Enemy/EnemyReaperState/Enemy_ReaperSpell.cs:23
if (((1 << collision.gameObject.layer) & whatIsTarget) != 0)
    combat.PerformAttackOnTarget(collision.transform, damageScaleData);
```

注意这里有一个真实 bug，见第 10.1 节。

### 6.10 技能物体伤害

技能物体有自己的基类 `SkillObject_Base`。它不继承 `Entity_Combat`，但核心思想一致：

```csharp
// Assets/Scripts/SkillSystem/SkillObject_Base.cs:36
protected void DamageEnemiesInRadius(Transform t, float radius)
```

内部仍然是：

```text
OverlapCircleAll
  -> IDamagable
  -> playerStats.GetAttackData(damageScaleData)
  -> TakeDamage(...)
  -> ApplyStausEffect(...)
```

这说明项目把“攻击检测入口”分成了两类：

- 角色近战：`Entity_Combat`
- 技能物体：`SkillObject_Base`

但它们共享两个真正稳定的底层协议：`AttackData` 和 `IDamagable`。

### 6.11 装备效果如何挂到战斗

战斗系统给装备效果留了事件扩展点。

命中造成物理伤害后：

```csharp
// Assets/Scripts/Entity/Entity_Combat.cs:66
OnDoingPhysicalDamage?.Invoke(attackData.physicalDamage);
```

吸血装备订阅这个事件：

```csharp
// Assets/Scripts/Data/ItemData/ItemEffects/ItemEffect_HealOnDoingDamage.cs:16
player.combat.OnDoingPhysicalDamage += HealOnDoingDamage;
```

受击后：

```csharp
// Assets/Scripts/Entity/Entity_Health.cs:90
OnTakingDamage?.Invoke();
```

冰爆装备订阅受击事件，然后在玩家周围 `1.5f` 范围内找敌人：

```csharp
// Assets/Scripts/Data/ItemData/ItemEffects/ItemEffect_IceBlastOnTakingDamage.cs:42
Collider2D[] enemies = Physics2D.OverlapCircleAll(player.transform.position, 1.5f, whatIsEnemy);
```

这是一种轻量事件系统：没有全局 EventBus，而是在具体组件上暴露强类型 C# event。优点是简单、可追踪；代价是订阅方必须拿到具体组件引用。

## 7. Unity 配置层必须知道的东西

### 7.1 Inspector 字段

`Entity_Combat` 必须配置：

- `basicAttackScale`：普攻倍率和异常参数。
- `targetCheck`：检测圆心，通常是角色前方或武器命中点。
- `targetCheckRadius`：检测半径。
- `whatIsTarget`：目标 LayerMask。玩家通常检测 Enemy，敌人通常检测 Player。

`Player_Combat` 额外配置：

- `counterRecovery`：反击失败时的恢复时间，默认 `0.1f`，见 `Assets/Scripts/Player/Player_Combat.cs:7`。
- `whatIsCounterable`：哪些层可以被反击。

`Entity_StatusHandler` 必须配置：

- `lightingStrikeVfx`：雷击爆发特效。
- `maximumCharge`：雷电叠层阈值，默认 `1`，见 `Assets/Scripts/Entity/Entity_StatusHandler.cs:16`。

### 7.2 Animator 参数

玩家 Controller 中能看到：

- `basicAttackIndex`：决定第几段普攻，`Assets/Animations/AnimatoerControllers/Characters/Player.controller:795`
- `jumpAttackTrigger`：跳劈落地动画触发，`Assets/Animations/AnimatoerControllers/Characters/Player.controller:807`
- `counterAttackPerformed`：反击成功/失败分支，`Assets/Animations/AnimatoerControllers/Characters/Player.controller:825`
- `attackSpeedMultiplier`：攻击状态播放速度，`Assets/Animations/AnimatoerControllers/Characters/Player.controller:831`

### 7.3 Animation Event 规则

攻击类动画至少有两类事件：

| 事件 | 含义 |
| --- | --- |
| `AttackTrigger()` | 命中帧，真正执行伤害判定 |
| `CurrentStateTrigger()` | 动画流程允许状态退出 |

敌人可反击攻击还会有：

| 事件 | 含义 |
| --- | --- |
| `EnableCounterWindow()` | 打开反击窗口，通常在前摇 |
| `DisableCounterWindow()` | 关闭反击窗口，通常在命中帧附近或之后 |

这些事件必须挂在带有 `Entity_AnimationTriggers` / `Enemy_AnimationTriggers` 的同一个动画 GameObject 上，否则 Unity 找不到方法。

## 8. 设计模式总结

| 模式/手法 | 项目里的体现 | 好处 | 代价 |
| --- | --- | --- | --- |
| Interface 隔离 | `IDamagable`, `ICounterable` | 攻击者不依赖具体目标类型 | 需要目标对象正确挂接口组件 |
| 组件组合 | Health/Combat/Stats/Status/VFX/SFX 分组件 | 每个组件职责清楚 | 跨组件引用较多，Prefab 配置要稳 |
| 状态机 | Player/Enemy 的 Attack/Counter/Spell 状态 | 攻击流程可控，动画退出明确 | 状态和 Animator 参数要同步维护 |
| Animation Event 桥接 | `Entity_AnimationTriggers` | 命中帧和动画动作对齐 | 方法名字符串无编译期检查 |
| 数据快照 | `AttackData` | 本次攻击数值稳定，方便传递 | 快照创建时机必须正确 |
| Serializable 配置数据 | `DamageScaleData` | Inspector 可调倍率 | 拼写错误 `phsycal` 已经固化为字段名 |
| 事件扩展 | `OnDoingPhysicalDamage`, `OnTakingDamage` | 装备效果无需改 Combat | 必须成对订阅/取消订阅 |

## 9. 正面例子 vs 反面例子

### 反面：把攻击全写在玩家 Update

```csharp
void Update()
{
    if (Input.GetKeyDown(KeyCode.Mouse0))
    {
        var hits = Physics2D.OverlapCircleAll(attackPoint.position, 1f);
        foreach (var hit in hits)
            hit.GetComponent<EnemyHealth>()?.TakeDamage(10);
    }
}
```

问题：

- 伤害时机和动画不同步。
- 只能打 `EnemyHealth`，宝箱/可破坏物/技能分身要继续加 if。
- 伤害值硬编码，属性、暴击、元素都塞不进去。
- 命中特效、音效、装备效果会继续污染这个方法。

### 正面：项目实际写法

```text
Animation Event
  -> Combat.PerformAttack()
  -> IDamagable.TakeDamage()
  -> Stats/Status/VFX/SFX/Event
```

好处是每层只处理自己的事：

- 动画层决定时机。
- Combat 层决定攻击范围和目标过滤。
- Stats 层决定数值。
- Health 层决定防御和死亡。
- Status/Item/VFX/SFX 层响应结果。

## 10. 当前代码里的坑和改进点

### 10.1 `PerformAttackOnTarget` 忽略了传入的 `DamageScaleData`

代码里先算了 `damageScale`：

```csharp
// Assets/Scripts/Entity/Entity_Combat.cs:135
DamageScaleData damageScale = damageScaleData == null ? basicAttackScale : damageScaleData;
```

但下一行仍然用的是 `basicAttackScale`：

```csharp
// Assets/Scripts/Entity/Entity_Combat.cs:136
AttackData attackData = stats.GetAttackData(basicAttackScale);
```

这会导致 Reaper spell 这类调用：

```csharp
// Assets/Scripts/Enemy/EnemyReaperState/Enemy_ReaperSpell.cs:25
combat.PerformAttackOnTarget(collision.transform, damageScaleData);
```

理论上传了法术倍率，实际仍可能按基础攻击倍率算。

建议修复：

```csharp
AttackData attackData = stats.GetAttackData(damageScale);
```

### 10.2 `PerformAttackOnTarget` 和 `PerformAttack` 获取接口方式不一致

范围攻击用：

```csharp
// Assets/Scripts/Entity/Entity_Combat.cs:35
target.GetComponentInParent<IDamagable>();
```

定点攻击用：

```csharp
// Assets/Scripts/Entity/Entity_Combat.cs:131
target.GetComponent<IDamagable>();
```

如果投射物撞到的是角色子物体 Collider，而 `IDamagable` 挂在父物体上，定点攻击会找不到。建议也改成 `GetComponentInParent<IDamagable>()`，`Entity_StatusHandler` 同理。

### 10.3 `OnDrawGizmos` 没判空

```csharp
// Assets/Scripts/Entity/Entity_Combat.cs:188
private void OnDrawGizmos()
{
    Gizmos.DrawWireSphere(targetCheck.position, targetCheckRadius);
}
```

如果某个 Prefab 还没拖 `targetCheck`，编辑器选中时可能报空引用。建议：

```csharp
if (targetCheck == null) return;
```

### 10.4 `OverlapCircleAll` 每次分配数组

`Physics2D.OverlapCircleAll` 会返回新数组。普攻频率不高时问题不大，但如果做高频旋转剑、召唤物、多段伤害，就会增加 GC 压力。

可优化为：

```text
Collider2D[] buffer = new Collider2D[16];
Physics2D.OverlapCircleNonAlloc(...)
```

### 10.5 状态命名和拼写有维护成本

存在一些拼写错误但已被代码依赖：

- `GetDectedColliders`
- `ApplyStausEffect`
- `EnableCounterWindoow`
- `phsycal`

短期不建议随手改名，因为 Unity 序列化字段和 Animation Event 方法名可能受影响。真正要改，应统一重构并检查动画事件和 Prefab 序列化。

### 10.6 `Entity_Health.UpdataHealthBar()` 判空逻辑有风险

```csharp
// Assets/Scripts/Entity/Entity_Health.cs:158
if (healthBar == null && healthBar.transform.parent.gameObject.activeSelf == false)
    return;
```

这里如果 `healthBar == null`，后半段还访问 `healthBar.transform`，会空引用。更合理的是：

```csharp
if (healthBar == null || healthBar.transform.parent.gameObject.activeSelf == false)
    return;
```

这个不是战斗伤害主链路 bug，但会影响受击后 UI 更新。

## 11. 迁移到自己项目时怎么做

最小可复用版本：

1. 建一个 `IDamagable` 接口，定义 `TakeDamage(...)`。
2. 攻击者挂 `Combat`，配置 `targetCheck`, `radius`, `LayerMask`。
3. 受击者挂 `Health`，实现 `IDamagable`。
4. 攻击动画命中帧添加 `AttackTrigger()`。
5. 动画物体挂一个 `AnimationTriggers` 桥接脚本。
6. 用 `DamageScaleData` 存倍率，用 `AttackData` 存本次攻击快照。
7. 再加元素、暴击、装备事件，不要一开始全塞满。

迁移时最容易漏的 Unity 配置：

- Animation Event 的方法名拼错。
- `targetCheck` 没拖。
- `whatIsTarget` LayerMask 没配。
- 目标 Collider 在子物体，接口却挂父物体，代码没用 `GetComponentInParent`。
- Animator 的速度参数名和代码里的 `attackSpeedMultiplier` 不一致。
- 装备事件订阅了但没有取消订阅。

## 12. FAQ

### Q1：为什么不是按下攻击键立刻扣血？

因为动作游戏的“命中”应该跟动画姿态对齐。按键只是进入攻击状态，真正扣血发生在 Animation Event 的命中帧。

### Q2：为什么 `CurrentStateTrigger()` 和 `AttackTrigger()` 要分开？

`AttackTrigger()` 表示“这一帧造成伤害”；`CurrentStateTrigger()` 表示“这个状态可以退出了”。有些动画命中后还有后摇，如果把两者合并，攻击状态会过早结束。

### Q3：为什么 Combat 里不直接调用 `Entity_Health`？

因为目标不一定是普通生命体。宝箱、技能物体、投射物都可能有自己的受击行为。`IDamagable` 让 Combat 只认“能不能被打”，不认“具体是什么”。

### Q4：为什么反击用 `ICounterable`，不用 `IDamagable`？

能被打和能被反击不是同一个能力。箭可以被反弹，敌人可以被眩晕，宝箱可以被打但不应该被反击。拆成两个接口是正确的边界。

### Q5：为什么元素异常在 `StatusHandler`，不在 `Health`？

`Health` 负责生命值和受击结算，`StatusHandler` 负责持续状态。这样冰冻、灼烧、感电不会把生命组件变成大杂烩。

### Q6：为什么技能物体没有完全复用 `Entity_Combat`？

技能物体有自己的生命周期和形态，比如分身、旋转剑、投射物。它们复用的是更底层的协议：`AttackData`、`IDamagable`、`Entity_StatusHandler`。这是合理的“复用底层，不强行复用入口”。

### Q7：为什么攻击速度不是直接改 `animator.speed`？

项目用的是 Animator 状态的速度参数 `attackSpeedMultiplier`。这样只影响配置了该速度参数的攻击状态，不会把待机、移动、受击等所有动画一起加速。

## 14. 总结

这个项目的战斗系统最值得学的不是某一行扣血公式，而是它的分层边界：

```text
状态机决定动作流程
动画事件决定精确命中时机
Combat 决定目标检测
Stats 决定数值快照
IDamagable 决定受击行为
Status/VFX/SFX/Event 决定反馈和扩展
```

如果你以后自己做 2D ARPG，建议先照着这个骨架搭最小版本：一个 `Combat`、一个 `IDamagable`、一个 `Health`、一个 `AnimationTriggers`。等普攻手感跑通，再加 `AttackData`、元素异常、反击、装备事件。这样系统会自然长出来，而不是一开始就被一个巨大的 `PlayerAttack.Update()` 拖住。
